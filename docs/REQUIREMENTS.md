# REQUIREMENTS

## 1. 文書の位置付け

この文書は、ぶいすぽ配信探索システムの要件とMVP境界を管理する。

現時点では企画・データソースPoC前のため、以下の区分を使用する。

- **Confirmed**: 現時点で確定している要件
- **Provisional**: MVP候補。PoC後に正式決定する
- **Out of Scope**: MVPには含めない
- **Open**: 未決定・要調査

## 2. 解決するユーザー課題

### R-001 [Confirmed]

複数のぶいすぽ所属メンバーを横断して配信アーカイブを探せること。

### R-002 [Confirmed]

特定メンバーの過去配信を探せること。

### R-003 [Confirmed]

特定ゲーム / topicの配信を複数メンバー横断で探せること。

### R-004 [Confirmed]

期間を指定して配信を絞り込めること。

### R-005 [Confirmed]

タイトル等のキーワードから配信を探せること。

## 3. MVP対象範囲

### 3.1 対象メンバー

**Provisional**

最初はVSPO! JPを対象とする。

対象チャンネルは、外部API側の組織情報に完全依存するのではなく、必要に応じて明示的なallowlistを管理する。

### 3.2 対象コンテンツ

**Provisional**

YouTube上の公開済み配信アーカイブを主対象とする。

MVPでは原則として以下を対象外とする予定。

- Shorts
- 切り抜き動画
- 通常の投稿動画
- 外部プラットフォームのみの配信

最終的な判定方法はデータソースPoC後に決定する。

### 3.3 データ期間

**Open**

初回投入期間は未決定。

候補:

- 直近数か月
- 直近1年
- 取得可能な全期間

MVP構築速度、API制限、データ量を確認して決める。

## 4. MVP機能要件

### F-001 メンバー一覧 / 絞り込み [Provisional]

ユーザーは対象メンバーを指定して配信を検索できる。

### F-002 ゲーム / topic絞り込み [Provisional]

ユーザーはゲームまたはtopicを指定して配信を検索できる。

ゲーム情報の取得元と信頼性はPoCで確認する。

### F-003 期間絞り込み [Provisional]

開始日・終了日を指定して配信を検索できる。

### F-004 キーワード検索 [Provisional]

タイトル等に対してキーワード検索できる。

### F-005 配信一覧表示 [Provisional]

検索結果に少なくとも以下を表示する。

- タイトル
- 配信者
- 配信日時
- ゲーム / topic
- 配信時間または終了日時
- YouTubeへのリンク

### F-006 並び替え [Provisional]

最低限、新しい順で表示できる。

古い順等は実装コストが低ければ追加する。

### F-007 配信情報保存 [Provisional]

外部APIから取得した配信情報をローカルDBへ保存できる。

保存可否・保持期間は利用規約を確認したうえで決定する。

### F-008 重複防止・更新 [Provisional]

同一の外部動画IDを重複登録せず、必要に応じて既存データを更新できる。

## 5. MVPで必要なデータ

データソースPoCでは、最低限次の項目を取得可能か確認する。

| 項目 | 必須度 | 状態 |
|---|---:|---|
| 外部動画ID | 必須 | Open |
| タイトル | 必須 | Open |
| 配信者 | 必須 | Open |
| チャンネルID | 必須 | Open |
| 配信URL | 必須 | Open |
| 配信開始日時 | 必須 | Open |
| 配信終了日時またはduration | 高 | Open |
| ゲーム / topic | 必須 | Open |
| 配信種別 | 高 | Open |
| 配信状態 | 高 | Open |
| サムネイル | 中 | Open |
| 説明文 | 低〜中 | Open |
| タグ | 低 | Open |

再生数・高評価数等はMVPでは不要とする。

## 6. MVP非機能要件

### NFR-001 コスト [Confirmed]

原則として無料で開発・MVP運用できる構成を優先する。

有料サービス導入時は理由と費用を明確にする。

### NFR-002 テスト可能性 [Confirmed]

外部APIアクセス、検索ロジック、DBアクセス等を必要に応じて分離し、自動テスト可能な構造を目指す。

### NFR-003 Secret管理 [Confirmed]

API Key、Token等のSecretをGitリポジトリへコミットしない。

### NFR-004 外部公開可能性 [Confirmed]

外部公開できる構成を意識する。

ただし、利用規約等により公開できない場合は自分専用システムとして運用する選択肢を残す。

### NFR-005 過剰設計回避 [Confirmed]

MVPではMicroservices、Redis、Queue、Search Engine等を必要性なく導入しない。

## 7. MVP Out of Scope

以下はMVPには含めない。

- ユーザーアカウント
- Authentication / Authorization
- お気に入り
- 視聴済み / 未視聴管理
- 視聴履歴
- おすすめ配信
- ML / LLMによるゲーム自動分類
- 専用全文検索エンジン
- Redis Cache
- Queue / Worker
- Microservices
- Kubernetes
- 高度な監視基盤
- 複数ゲームを配信内の時間区間単位で管理する機能

必要性が発生した場合はMVP完成後に再評価する。
